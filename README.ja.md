# jmacat

[English](README.md) | [日本語]

**気象庁の地震カタログを、そのまま解析できる表に変換します。**

気象庁「地震月報（カタログ編）」の震源データ1年分を、コマンド1つで Parquet
または CSV にします。座標・深さ・マグニチュード・タイムゾーンは、いずれも
正しく変換した状態で出力されます。**研究・教育用**のツールです。

```sh
uv run jmacat fetch --year 2023 --output events.parquet
```

## このツールが解決する問題

気象庁は震源カタログを、96バイト固定長レコードの ZIP として公開しています。
これを表にするには、アーカイブをダウンロードして、デコーダを自分で書くことに
なります。

**Before** — 気象庁が配布しているままの1レコード：

```
J2023010100080150 012 354059 100 1403927 136 50     03v   721   3110NEAR CHOSHI CITY          9A
```

ここから、度・分（小数）を10進度に変換し、南緯と負のマグニチュードを処理し、
2種類ある深さのエンコーディングを判別し、時刻が JST であることを踏まえたうえで、
CSV に組み立てる必要があります。

**After** — 同じレコードが、`events.csv` の最初のデータ行になったもの：

```csv
record_type,origin_time_utc,origin_time_jst,second_is_known,latitude_deg,latitude_minutes_are_known,longitude_deg,longitude_minutes_are_known,depth_km,magnitude,magnitude_type,magnitude_2,magnitude_type_2,district,region_number,region_name,station_count
J,2022-12-31T15:08:01.500Z,2023-01-01T00:08:01.500+09:00,True,35.6765,True,140.6545,True,50.0,0.3,v,,,3,110,NEAR CHOSHI CITY,9
```

`354059` は 35.4059 ではなく**北緯 35.6765 度**に、`1403927` は**東経 140.6545 度**に
なっています。` 50  ` は 0.50 ではなく**深さ 50.0 km** です。そして JST の
発生時刻には UTC の対が付くので、USGS や ISC と結合するときに9時間の差を
思い出す必要がありません。

この変換が、このツールのすべてです。コード量そのものは多くありません。しかし
「静かに間違える」種類のコードです。それが次節の内容です。

## なぜ50行のスクリプトでは足りないのか

以下の落とし穴は、いずれも**エラーを出さずに失敗**します。例外も警告も出ず、
もっともらしい値が返り、そのまま図表に残ります。

- **座標は「度＋分（小数）」であって10進度ではない。** `354059` を10進度の
  35.4059 として読むと、震央が**約27 km**ずれます。
- **符号は度フィールドの先頭カラムにある。** このカラムを切り落とすと、経度
  `-178` の `KERMADEC ISL., N.Z.L.` が西経178度ではなく東経178度、つまり地球の
  反対側になります。`h2023` では緯度の度フィールドに `-` を含むレコードが45件、
  経度側が18件あります。
- **古いレコードは分の小数部が空白。** 1923年の相模湾のレコードでは、緯度の分が
  `06  ` です。これは 0.06 分ではなく **6.00 分**です。`int(s.strip())/100` は
  0.06 を返し、**約11 km**の誤差になります。
- **深さは1つのフィールドに2種類のエンコーディングがある。** ` 50  ` は 50 km
  （整数km、末尾2桁が空白）、` 2645` は 26.45 km です。前者を後者として読むと
  0.50 km になります。また `h1919` にある「末尾1桁だけ空白」の形を整数kmとして
  読むと、297件が最深**5,400 km**——外核の内部——に置かれます。
- **マグニチュードは負になりうる。** `-6` は M-0.6、`A0`/`B0`/`C0` はそれぞれ
  M-1.0/-2.0/-3.0 です。素朴な `int(field)/10` は前者を M-6.0 とし、後者では
  例外を投げます。`h2023` では24,882件——約10件に1件——が負の値です。
- **時刻は UTC ではなく JST。** 仕様上これが明記されているのは**英語版**の
  フォーマット表だけで、日本語版のページはタイムゾーンに一切触れていません。
  USGS や ISC と比較するには9時間のシフトが必要です。

いずれもエラーにならないため、「動いた」ことだけを確認するテストでは1つも
検出できません。それぞれの落とし穴は、それを踏む実レコードとともに
[`docs/jma-hypocenter-format.md`](docs/jma-hypocenter-format.md)（本プロジェクトの
一次情報）に記載し、期待値を仕様または引用元レコードまで追跡できるテストで
担保しています。

ObsPy はこの形式を読めません。ObsPy のイベント読み込みは QuakeML、NDK、ZMAP、
CMTSOLUTION、Nordic、PDE などに対応していますが、気象庁の震源カタログは対象外
です。個別の変換スクリプトは GitHub 上に複数の言語で存在しますが、いずれも
一から書かれたもので、利用者はほとんど付いていません。

## インストール

Python 3.11 以降が必要です。

**jmacat はまだ PyPI に公開されていません**ので、クローンしてインストール
してください。uv と pip の両方の手順を示します。どちらでも同じ `jmacat`
コマンドが入ります。

```sh
git clone https://github.com/uonoko1/jmacat && cd jmacat

# uv を使う場合（依存解決と環境作成をまとめてやってくれるので推奨）
uv sync
uv run jmacat --version

# pip を使う場合
python -m venv .venv && . .venv/bin/activate
pip install -e .
jmacat --version
```

公開後は `uv tool install jmacat` あるいは `pip install jmacat` だけで済みます。

## 最小の例

1年分を取得して Parquet に書き出します。アーカイブ（約7 MB）は一度だけ
ダウンロードされてキャッシュされるので、2回目以降はネットワーク通信が
発生しません。

```console
$ jmacat fetch --year 2023 --output events.parquet
Wrote 257,020 events to events.parquet (parquet).
Read 257,020 records from the 2023 catalog.
```

日本の地震活動まる1年分——257,020イベント——が、ノート PC で約11秒、
8.1 MB のファイルになります。CSV で出力する場合は `--format csv` を指定します。

取得と同時に絞り込むこともできます。

```sh
jmacat fetch --year 2023 --area ishikawa --min-magnitude 3.0 --format csv --output noto.csv
```

`--version` と `--help` は期待どおりに動作します。また、失敗時はトレースバック
ではなくメッセージを出して非ゼロで終了します。

## このツールがしないこと

- **最近の地震は取得できません。** 確定値のカタログは数年遅れで公開されます。
  2026-08-30 時点で、公開されている最新年は2023年です。
- **地震学的な解析はしません。** デクラスタリング、b値の推定、検知能力
  （Mc）の評価、再決定のいずれも行いません。きれいな表を渡すところまでが
  担当で、解析は利用者の側の仕事です。
- **気象庁の他の形式は読みません。** デックファイル、検測値（走時・相）データ、
  メカニズム解には対応していません。震源カタログのみです。
- **ポリゴンによる地理判定はしません。** `--area` は矩形（bounding box）です。
- **31フィールドすべてはデコードしていません。** デコード済みは16フィールドで、
  残り11フィールドは空欄で出力するのではなく、列自体を出しません。
  「出力に含まれていないレコードフィールド」を参照してください。
- **気象庁のデータを再配布しません。** データは利用者自身が、自分の環境に
  取得します。

## 適用範囲と安全上の注意

jmacat は、公開済みの確定した地震カタログを、解析できる表に変換するための
ツールです。想定している用途はいずれも遡及的なものです。Gutenberg-Richter の
b値の計算、デクラスタリング済みカタログの作成、震源がレコード上でどう符号化
されているかを地震学の授業で教えること、ハザードモデルの入力ファイルの作成
などです。設計のすべてがそれに従っています——読み込むカタログは数年遅れであり、
アーカイブはポーリングせずディスクにキャッシュし、出力は静的なファイルです。

そして、それがこのツールに適した用途のすべてです。**本ツールは公式の防災情報に
代わるものではなく、避難の判断、リアルタイムの警報、その他人命の安全に関わる
自動的な意思決定に使用してはなりません。**

これは形式的な免責ではありません。データ自体がそのような用途を支えられない
からです。確定カタログの公開は数年遅れであり、そこに含まれる最新のイベントは、
このツールが目にする時点ですでに過去のものです——2026-08-30 時点で利用できる
最新年は2023年であり、2024年の能登半島地震はこのデータセットには**含まれて
いません**。jmacat の上に「地震を監視しているように見える」パイプラインを
組んだとしても、それが見ているのは地震に反応して変化することのないファイルです。

警報、現在の地震活動、避難に関する情報など、運用に関わるものについては、
公式の情報源を利用してください。

- **気象庁** — 地震・津波情報、警報：
  <https://www.jma.go.jp/bosai/map.html>
- **お住まいの自治体** — 避難情報および避難所の情報。
- **内閣府 防災情報** — <https://www.bousai.go.jp/>

また、本プロジェクトは**実験的**なものです。この形のツールが日本の研究者に
とって有用かどうかを確かめるために作られており、必要性が確立しているから
作られたわけではありません。出力形式は変更される可能性があり、正確性に
ついて主張できるのは、テストがカバーしている範囲に限られます。

## 出典の記載とデータの取り扱い

### データの出所

本ツールが扱う地震データは、すべて**気象庁**が「地震月報（カタログ編）」
として公開しているものです。

| 内容 | URL |
| --- | --- |
| 震源データファイル一覧 | <https://www.data.jma.go.jp/eqev/data/bulletin/hypo.html> |
| 年ごとの震源アーカイブ | `https://www.data.jma.go.jp/eqev/data/bulletin/data/hypo/h{year}.zip` |
| レコードフォーマット仕様 | <https://www.data.jma.go.jp/eqev/data/bulletin/data/format/hypfmt_e.html> |
| 震央地名表（付録 1.A.3） | <https://www.data.jma.go.jp/eqev/data/bulletin/catalog/appendix/appendixj.html> |

### 本リポジトリはカタログデータを再配布しません

アーカイブは実行時に**利用者自身の環境**へ取得され、そこにキャッシュされます
（[`docs/catalog-cache.md`](docs/catalog-cache.md) を参照）。`h{year}.zip` は
本リポジトリにコミットされていません。`.gitignore` が `*.zip` と
`h[0-9][0-9][0-9][0-9]` を除外しているので、誤ってコミットすることもできません。

例外は2つだけで、いずれも出所と出典を
[`tests/infrastructure/fixtures/README.md`](tests/infrastructure/fixtures/README.md)
に明記した、ごく小さな記録済みテストフィクスチャです。`h1919_sample.zip`
（651バイト、`h1919` の先頭12レコード）と `h2024_404.html`（2,203バイト、
気象庁の404ページ。カタログデータを含みません）です。

気象庁の
[気象庁ホームページについて](https://www.jma.go.jp/jma/kishou/info/coment.html)
（2026-08-30 閲覧）には、次のように記載されています。

> 気象庁ホームページで公開している情報（以下「コンテンツ」といいます。）は、権利表記の記載がない限り「公共データ利用規約（第1.0版）」に準拠した利用条件の下で、利用することができます。 利用に当たっては、公共データ利用規約（第 1.0 版）を遵守してください。

すなわち、ページ独自の権利表記がない限り、コンテンツは
**公共データ利用規約（第1.0版）**（PDL1.0）のもとで利用できます。規約本体は
デジタル庁が
<https://www.digital.go.jp/resources/open_data/public_data_license_v1.0>
で公開しています。

正確を期すために2点補足します。いずれも取り違えやすい点です。

- PDL1.0（2024-07-05 制定）は、従来の**政府標準利用規約の後継**です。同一の
  文書ではなく、気象庁のページが現在名指ししているのはこちらです。
- PDL1.0 は、CC BY 4.0 と互換性があることを明示しています
  （「クリエイティブ・コモンズ・ライセンスの表示4.0 国際ライセンスに規定される
  著作権利用許諾条件（以下「CC BY」といいます。）と互換性があります。」）。
  したがって CC BY 4.0 の形式による出典表示でも要件を満たしますが、実際に
  記載する文言は、以下の気象庁自身の記載例に従うのが確実です。

### 規約が求めていること

気象庁のページには、記載方法が例示されています。出典表示の要件を言い換えると
それはもう要件ではなくなるため、原文のまま引用します。

> (1)　出典の記載について
>
> コンテンツを利用する際は出典を記載してください。出典の記載方法は以下のとおりです。
>
> （出典記載例）
>
> 出典：気象庁ホームページ　（当該ページのURL）
>
> 出典：○○気象台ホームページ （当該ページのURL）
>
> 「図・写真等の名称」（気象庁ホームページより）
>
> コンテンツを編集・加工等して利用する場合は、上記出典とは別に、編集・加工等を行ったことを記載してください。
> また編集・加工した情報を、あたかも国（又は府省等）が作成したかのような態様で公表・利用してはいけません。
>
> （コンテンツを編集・加工等して利用する場合の記載例）
>
> 気象庁「図・写真等の名称」 （当該ページのURL）を加工して作成
>
> 気象庁「○○調査」をもとに△△株式会社作成

義務は3つです。

1. **出典を記載する。** 出典と、取得したページの URL を示します。
2. **編集・加工した場合は、その旨を記載する。** これは**上記出典とは別に**
   記載する必要があります。PDL1.0 はさらに、加工の主体を記載することを
   求めています（「編集・加工等を行ったこと及びその主体を記載してください」）。
3. **加工した情報を、国が作成したかのように公表・利用しない。** 派生データを
   政府の無加工の成果物であるかのような形で公開することは、明確に禁じられて
   います。

### 利用者が実際に書くべきこと

jmacat が出力するものは、すべて**加工済み**の気象庁データです。固定長レコード
から物理量へデコードし、絞り込み、別形式へ直列化しているためです。したがって
jmacat の出力には義務2が**常に**適用されます。ここが最も間違えやすい点です。
出典を書くだけでは足りません。

**jmacat の出力から得た結果を公表する場合**（論文、図、ポスター、学位論文など）
は、カタログの出典と、加工した旨を記載してください。記載例：

> 出典：気象庁ホームページ（https://www.data.jma.go.jp/eqev/data/bulletin/hypo.html）を加工して作成
>
> 気象庁「地震月報（カタログ編）」（https://www.data.jma.go.jp/eqev/data/bulletin/hypo.html）をもとに著者が jmacat を用いて作成

**出力そのものを再配布する場合**（派生した CSV や Parquet、リリース成果物、
データセットとしての登録など）は、同じ表示を**ファイルに付随させて**——README、
データ説明、メタデータのフィールドなどに——記載する必要があります。それを引用
する論文の側だけに書くのでは足りません。加工済みの気象庁データであること、
および加工の主体を明示し、気象庁の公式な成果物であるかのように示さないで
ください。

なお PDL1.0 の免責条項により、コンテンツの利用（加工した派生物の利用を含む）に
ついて国は一切の責任を負いません。これは本プロジェクト自身の無保証条項
（[`LICENSE`](LICENSE)）とは別のものです。

## サンプルノートブックを置いていない理由

本リポジトリには、意図的にサンプルノートブックを置いていません。jmacat の
出力は通常の Parquet / CSV ファイルなので、jmacat の仕事が終わる地点が、
そのまま利用者自身のツールに引き継がれる地点です。`pandas.read_parquet` を
見せるノートブックは、このツールではなく pandas の説明になります。その一方で、
本プロジェクトが依存していない pandas・matplotlib・Jupyter カーネルを、
ドキュメントを再現するための必要環境に加えることになり、さらに、どのゲートも
検証しないセル出力がコミットされ、気づかれないまま古くなっていきます。
README に載せたコマンドはすべて実際に実行して出力をそのまま貼っており、
スキーマ表はテストがコードと突き合わせています。ノートブックだけが、
正しさを担保する仕組みのない成果物になってしまいます。
